# 前段路線比較：什麼證據才能支持流程選擇

日期：2026-09-30。狀態：對照設計，尚未執行生成比較；目前沒有「最佳路線」結論。

## 1. 當前判斷

原流程 A 有 catworld 個案可參考，適合作為研究基準；不能因為流程寫完整，就把「先逐照風格化、再重建四視圖」定為所有玩家都必須經過的上線流程。

對本產品，原照身份與 cat.png 的整體外觀是共同門檻。評估要保留臉、比例、花色和美術表現；不能以動畫容易或成本低為由降低外觀標準。

優先驗證的改進是減少不必要的影像重生成，同時保留原照證據與品質檢查。這是工程假設，尚未證明直接合併生成比拆步生成更好。

## 2. 四個需要釐清的假設

1. **同姿勢風格化是否必要：** 它有助於定位風格轉換的錯誤，但可能增加身份漂移、人工校正與生成成本。直接從原照和風格參考生成站姿，可能更少漂移，也可能因同時處理兩種任務而更差，必須比較。
2. **四個 AI 視角是否總是優於單圖：** 一致的多視角有助於補足不同表面；矛盾的生成圖可能引入錯誤。多張生成圖不是多次真實觀測，不能把猜測當證據。
3. **2D 切面強度是否影響 3D：** 強烈三角形色階可能被解讀成紋理或形狀起伏，造成花色噪點或不合理面形；本專案尚未量測這個影響。參考圖的自然形體與乾淨花色需保留，最終切面由 3D 程序控制的比重需要實驗。
4. **照片直接建模是否更保真：** 可作適用姿勢的對照。現有照片多為趴、躺、坐姿，直接產生這些姿勢的模型可能不適合動畫；不能拿可愛靜態公仔的效果與可動畫站姿角色作不公平比較。

Tripo 提供單圖與多視角的獨立入口，並沒有規定輸入必須先畫成 low-poly。先風格化是本專案的美術策略。[單圖介面](https://developers.tripo3d.ai/en/docs/generation-image-to-model/standard)、[多視角介面](https://developers.tripo3d.ai/en/docs/generation-multiview-to-model/standard)

## 3. 逐項對照，不一次改所有變因

### E1：拆步風格化 vs 直接站姿生成

| 條件 | A：現有研究基準 | B：優先測試的簡化路線 |
| --- | --- | --- |
| 身份來源 | 同一組原照與確認特徵清單 | 相同 |
| 風格標準 | cat.png | 相同 |
| 影像處理 | 原照 → 同姿勢風格圖 → 標準站姿四視圖 | 原照＋cat.png＋身份清單 → 直接標準站姿四視圖 |
| 送入 Tripo | 通過一致性檢查的四視圖 | 相同驗收規格的四視圖 |
| Tripo 設定 | front-end-profile 的基準 | 同一設定與種子 |
| 後處理 | 相同初始規則，修改均記錄 | 相同 |

比較身份漂移、姿勢與花色矛盾、返工次數、最終美術品質。A 的中間圖方便 debug，不等於 B 必須補做該中間步驟。B 若失敗，可使用 A 分解原因。

### E2：單張站姿圖 vs 已驗收多視角

固定 E1 中同一套通過驗收的參考資料，分別測：

- S-front：只使用該套的 front 圖，呼叫 image-to-model。
- M-four：使用該套的 front／left／back／right，呼叫 multiview-to-model。

其餘共同參數固定。單圖請求使用 input，並明確 enable_image_autofix=false；不把多視角的 inputs 陣列原封不動搬過去。現有離線組裝器只覆蓋 M-four，S-front 需要另外實作與預檢。

這組比較量測「添加其他視角後的效果」；不把兩個 endpoint 當成內部演算法完全相同。front 單圖可能有腿重疊、身長不明等限制；若另測三分之四主圖，另列 S-threequarter，不能偷偷替換 S-front 後仍宣稱只改視角數量。

其餘原照即使未送入 Tripo，也照常參與身份驗收。評分必須檢查背面和兩側，不只看模型正面。因為兩組沿用已產生的四視圖，這次實測成本也不能直接當成未來「只產一張主圖」的完整成本。

### E3：細切面前置 vs 3D 後置

在 E1/E2 確定有可用結果後，才比較參考圖切面強度：

- 保留 cat.png 較明顯的多邊形色階。
- 保留相同自然比例、臉部結構與花色，但減少細碎切面明暗；更多切面表現在 3D 幾何與表面程序完成。

先檢查兩套參考圖是否已改變花色／形狀；若有，不能把模型結果全歸因於切面強度。這是難以完全控制的生成實驗，需要重複樣本。

### D：先建模再風格化的條件式對照

當原照具有適合建模的姿勢與可見部位時，可以比較原照直接建模，再處理形體、花色與切面。若先生成中性站姿才能使用此路線，必須把該步生成的誤差和成本一起計入。

先建模再風格化不會自動修好粗略眼眶、臉頰或四肢比例；單純減面和 flat shading 不足以保證接近 cat.png。此路線不得因少一次風格圖而預先判定為最佳。

## 4. 如何判定哪條路線值得採用

先看硬條件：

- 原照確認的個體特徵完整，未把隱藏面猜測冒充觀測。
- 多視角呈現符合 cat.png 的造型、臉部、切面、花色與材質標準。
- 幾何足以繼續骨架和變形測試，沒有多腿、融合等結構缺陷。

只有都達標時，再比較無人工通過率、修正時間、失敗次數、實際 API 點數、生成耗時與檔案大小。若單圖背面花色不合格，即使成本較低，也不能勝出；如果多視角引入結構矛盾，也不能只因輸入較多就勝出。

第一輪各做一個案例篩出系統性問題；有競爭力的路線再用至少三組預先指定種子測穩定性，保留所有失敗與返工，不能只展示最好的一隻。最後擴到不同貓；同一隻貓重跑三次不等於跨個體泛化測試。

## 5. 決策狀態

- A 保留為當前研究基準，既有設定與證據不改寫。
- B 是最值得先測的流程簡化假設，尚未選為正式流程。
- 單圖／多視角與切面強度分開比較，不預先宣布四視角必需或單圖更好。
- 現有證據尚不能支持最佳流程、商業成功率或完整等待時間承諾。

正式流程可能依照片覆蓋與參考圖一致性選擇分支，但分支判斷規則也要在測試集驗證後才能上線。
